# 要件定義書: Promo Forecast Skill

## 1. プロジェクト目的

定番需要（Baseline）と販促リフト（Promotion Lift）を構造的に分離し、将来の販促施策が「どれだけの数量増」と「どれだけの利益増（ROI）」を生むかを高精度に予測・シミュレーションする。

## 2. ビジネス要件

- **定番・リフトの分離**: 実績数量を「施策がなかった場合の需要」と「施策による上乗せ」に解体すること
- **ROIの可視化**: 粗利ベースの投資対効果を算出すること
- **ランク別分析**: 施策の規模（S/A/B/L）に応じた効率性をランキング化すること
- **不確実性の考慮**: 80%信頼区間（10%・90%分位点）を提示し、安全在庫の判断材料を提供すること
- **What-Ifシミュレーション**: 価格・チラシの有無を変更し、増分粗利をリアルタイム確認できること

## 3. 機能要件

### Step 0: データ生成
- 過去5年間の日次POSデータ生成（5品目）
- 4段階の販促ランク（激推し/通常/プチ安/長期重点）を含む販促カレンダー生成
- 季節性、成長トレンド、非線形な価格弾力性のシミュレーション
- **CPG現実性の注入**（実データに近い挙動を再現）:
  - 買いだめ反動（forward-buying / pantry loading）: 特売リフトの一定割合を後続N日の定番需要から先食いし、特売後にベースを凹ませる（`PULLFORWARD_FRAC` / `PULLFORWARD_DAYS`）
  - 欠品打ち切り（stockout censoring）: 一部の非特売日で在庫切れにより実売を真の需要より過少に観測し、`stockout` フラグを付与（`STOCKOUT_RATE` / `STOCKOUT_CENSOR`）
  - 販促飽和（wear-out）: 直近の特売頻度に比例してリフトを減衰させ、頻発販促の逓減を表現（`SATURATION_WINDOW` / `SATURATION_STRENGTH`）

### Step 1: 需要分解
- 曜日考慮型移動平均によるベースラインの推定（特売日はマスクして定番推定の汚染を防止）
- **欠品日（`stockout`）をベースライン推定から除外**: 打ち切り観測がベースを過少に引っ張るのを防止し、周辺日から補完
- **リフトは特売日のみに計上**（非特売日のリフトは0）。移動平均ノイズの偽リフトを排除し、リフト総量バイアスを±2%以内に
- 重複する施策の名称連結・費用合算処理
- 将来180日の共変量補完（予測用の価格・チラシプランを仮定）

### Step 2: 戦略予測
- LightGBM Hybridモデル（中立共変量カウンターファクチュアル方式）
- LightGBM単体モデル（比較用）
- Optunaによるlags自動最適化（n_trials=5）
- **80%信頼区間（キャリブレーション済み）**: バックテスト残差の経験分位点で較正（split-conformal方式）。生のLGBM分位点では実カバレッジが約26%だったため、実誤差ベースで区間幅を決定し約80%に補正
- **バイアス指標**: WAPE/MAPEに加え方向性バイアス `sum(pred-actual)/sum(actual)` を算出（+=過剰在庫リスク / −=欠品リスク）
- **共変量リーク対策**: 中立共変量の窓を予測開始日から日付明示スライス（末尾スライスの偶然依存を排除）

### Step 3: ダッシュボード（9タブ構成）
- **📖 利用法・解説**: クイックスタート・各タブの役割・モデルロジック・指標の読み方
- **需要分解**: 面グラフ + 販促イベントアノテーション + 日次/週次/月次集約切替
- **LGBM 360日展望**: 360日展望チャート（過去180日検証 + 未来180日予測）
- **Hybrid予測**: Hybridモデルの80%信頼区間付き可視化
- **販促ROI分析**: 散布図・ランク別集計表
- **品目横断ポートフォリオ**: 全品目の費用vsROI散布図 + ランク別積み上げ棒 + ROIマトリックス
- **戦略シミュレーター**: 価格・チラシ変更 → 増分粗利をリアルタイム表示
- **価格弾力性カーブ**: 価格10円刻みスイープ → 最適価格の自動表示
- **販促カレンダー入力**: 既存カレンダー編集 + 新規プラン追加 → ガントチャート → 予測パイプライン再実行 → シミュレーター連携

### Step 4: レポート出力（オプション）
- 全品目のHTML静的レポート生成

## 4. 非機能要件

- **Polars First**: データ処理の100%をPolarsで実施
- **Path Resilience**: `sys.path`介入によるWindows環境での堅牢なモジュール解決
- **Unit Testing**: pytestで42件のロジック整合性チェック
- **検証スクリプト**（合成データ専用）:
  - `scripts/validate_decomposition.py`: `ground_truth.csv` の真値と推定Base/Liftを照合（Base WAPE・Bias・Lift総量比・検知Precision/Recall）
  - `scripts/validate_walkforward.py`: walk-forward（複数origin）バックテストでWAPE平均±標準偏差・最悪originを出力し、精度の安定性を評価（horizon=30日/stride=30日）

## 5. ビジネスルール定義

| ルール | 定義 |
|--------|------|
| 販促検知閾値 | 値引き率 > 10%、またはカレンダー登録あり |
| 信頼区間 | 80%（分位点: 0.1 / 0.9） |
| ROI計算式 | `(増分粗利 / 直接販促費用) × 100` |
| 買いだめ反動 | リフトの `PULLFORWARD_FRAC`(=0.35) を後続 `PULLFORWARD_DAYS`(=7)日のベースから先食い |
| 欠品打ち切り | 非特売日の `STOCKOUT_RATE`(=0.03) を `STOCKOUT_CENSOR`(=0.55) 倍に censoring |
| 販促飽和 | 直近 `SATURATION_WINDOW`(=60)日の特売頻度に比例し最大 `SATURATION_STRENGTH`(=0.5) 減衰 |
| 販促ランク S | 「激推し」を含む販促名 |
| 販促ランク A | 「通常」を含む販促名 |
| 販促ランク B | 「プチ安」を含む販促名 |
| 販促ランク L | 「長期」を含む販促名 |

## 6. 除外スコープ

- リアルタイムPOSデータ連携（本POCはCSVファイルを入力とする）
- キャンペーンコスト（チラシ印刷費等）の自動取込（手動入力カレンダーで代替）
- マルチチャネル・店舗別予測（品目単位のみ）

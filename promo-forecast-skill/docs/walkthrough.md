## [2026-06-13] 信頼性の修正 + 機能追加（専門家レビュー）

消費財需要予測の専門家レビューに基づく一連の修正。詳細な残作業は `docs/BACKLOG.md` を参照。

### 信頼性の修正
- **共変量リーク堅牢化**: 中立共変量の窓を末尾スライス（`covariate_series[-horizon:]`、偶然のアラインメント依存）から予測開始日基準の日付明示スライス（`_slice_forecast_window`）に変更。`libs/models.py`
- **ゼロ処理 / 指標整合**: `calculate_metrics` が全ゼロ実績で `(0.0, 0.0)` を返し「完璧な予測」と誤表示する問題を `NaN` に修正。WAPE分母を `sum(|actual|)` に統一。`libs/data_utils.py`
- **M1: 信頼区間キャリブレーション**: 80%区間の実カバレッジが **26%** だった問題を、バックテスト残差の経験分位点（split-conformal方式）で **80%** に補正。`calibrate_bands()` 新設。
- **M2: リフトの非対称クリップ修正**: 非特売日の偽リフト（4〜5%）を排除し、リフト総量バイアスを 104〜106% → **98〜102%** に改善。`step1_decompose_demand.py`
- **M3: シミュレーターのリスク幅**: 固定±10%ダミーをモデルの実分位点（10%/90%）に差し替え。`step3_show_dashboard.py`
- **M4: バイアス指標**: `calculate_bias()` を新設し、方向性バイアス（+過剰在庫 / −欠品）をダッシュボードの精度パネルに表示。

### 機能追加
- **利用法・解説タブ**: ダッシュボード先頭に解説タブを追加（全9タブ化）。
- **A1: 買いだめ反動（forward-buying）**: `step0` に pantry loading を注入（特売後にベースが凹む）。従来分解がリフトを実態の84-86%に過小評価していたことを `validate_decomposition` で定量化。`PULLFORWARD_FRAC` / `PULLFORWARD_DAYS`
- **A3: 欠品打ち切り補正**: `step0` で非特売日を稀に censoring し `stockout` フラグ付与、`step1` でベース推定から除外。`STOCKOUT_RATE` / `STOCKOUT_CENSOR`
- **A4: 販促飽和（wear-out）**: 直近の特売頻度に比例してリフトを減衰（高頻度期に38%減衰）。`SATURATION_WINDOW` / `SATURATION_STRENGTH`
- **A6: walk-forward 検証**: `scripts/validate_walkforward.py` で複数originバックテスト（WAPE平均±標準偏差・最悪origin）。
- **分解精度検証**: `scripts/validate_decomposition.py` で `ground_truth` と推定値を照合（合成データ専用）。

### 高速化（調査結論）
- 品目ループの並列化は**実測で逆効果**（LightGBMが各品目で全コア飽和済み。threads: 93→121s / loky: 93→125s）のため不採用、逐次のまま。
- ダッシュボードの価格弾力性タブが sim モデルを再fitしていた重複を除去（キャッシュ済みモデルを再利用）。

## [2026-04-15] 需要分解チャート（日次）の積み上げバグ修正

### 修正の背景と事象
Streamlitダッシュボードの「需要分解」タブにおいて、週次や月次の集約表示では「定番需要（青）」の上に「特売リフト（赤）」が正しく積み上がって描画されるものの、日次（daily）表示のときだけ両者が積み上がらず、重なって表示される（あるいは予期せぬ描画になる）という事象が報告されました。

### 原因の特定
Plotly の `stackgroup` パラメータは、複数のトレース（グラフ要素）をグループ化して積み上げ（Area chart）を行う機能ですが、内部的には与えられた `x`（座標軸）の値をマッチングして積み上げ計算を行います。

週次や月次の処理では、Polarsの `.agg()` によってインデックスがクリーンな新しいDataFrameが生成されていたため、Plotlyが正常に `x` 軸を解釈できました。
しかし日次表示の場合、元のデータフレームから抽出されたSeries（あるいはPandasのSeries）がそのまま渡されており、Polars/Pandasの内部的なインデックスやメタデータがPlotlyのスタック処理を阻害し、正常な積み上げ計算が行われていませんでした。

### 修正内容 (`libs/chart_builder.py`)
1. **確実なソートの実施**: 
   集約処理を行わない「日次」のデータであっても、Plotlyへデータを渡す前に `plot_df.sort("date")` を明示的に呼び出し、日付順に整列されたPolars DataFrameを構築するように統一しました。
2. **純粋なPythonリストへの変換**:
   Seriesオブジェクトを直接渡すのをやめ、`.to_list()` メソッドを使って `x`（日付）と `y`（需要）の値を純粋な Python の List 型として抽出してから Plotly に渡すように変更しました。これにより、メタデータによる予期せぬマッチング不全を排除しました。
3. **明示的な `fillcolor` の指定**:
   `stackgroup` だけではまれに塗りつぶし色が変わることがあるため、`fillcolor` を明示的に指定し、意図した色で確実に面グラフが描画されるよう補強しました。

### 確認手順
Streamlitを起動（またはブラウザをリロード）し、「需要分解」タブを開きます。「集計単位」を「日次」にした際、特売リフトの赤い面グラフが定番需要の青い面グラフの上に正しく乗って描画されていれば修正完了です。

# essay-note-template（汎用論考テンプレ）

阿波説 Vault `D:\Vault\awa` で **神格・氏族・天皇伝承・渡来人・地政学などの論考型ノート** を
近代化（旧フォーマット→統一形式）または新規作成する際の標準テンプレート。

[[shrine-note-template]] が「神社」専用なのに対し、本テンプレは **神社以外**（祭神そのものの
神格論、氏族論、天皇・伝承論、考古・地政学論考）に使う。神社ノートには使わない。

## 使い分け

| ノート種別 | テンプレ | 配置先(例) |
|---|---|---|
| 神社（式内社・式外社） | [[shrine-note-template]] | `式内社/...` |
| 神格（祭神そのものの論） | **本テンプレ** | `理論・研究/03_氏族・系譜/神々の系譜/...` |
| 氏族・系図 | **本テンプレ** | `理論・研究/03_氏族・系譜/各氏族の研究/...` |
| 天皇・伝承・渡来人・地政学・考古 | **本テンプレ** | `理論・研究/01_〜05_/...` |
| 目次・MOC・ポータル・索引・dataview動的 | **テンプレ非適用**（触らない） | — |

## 近代化の鉄則（最重要・L-004 / L-005）

近代化＝**内容保存リストラ（content-preserving restructuring）**であって、**新規主張の生成ではない**。

1. **既存の主張は一つも失わない** — 旧ノートの全アサーションが、再編後も（並べ替え・節分けされて）残ること。
2. **埋めるために捏造しない** — テンプレの節が既存材料で埋まらないなら、**その節は省く or 薄いまま**にする。空欄を埋めるために新しい史実主張を書かない。
3. **通説と阿波説を分離** — 記紀・通説の記述と、阿波説の飛躍（比定・読み替え）を必ず別の層に置く。
4. **素材ノートの断定を継承しない** — 一次データノートや既存ノートが「証明する」「物証」「〜説が有力」と断定調で書いていても、それを新ノートにそのまま引き継がない。一次事実だけ抽出し、解釈・帰属は `[!note]` で仮説隔離する。考古系では特に、通説を一次確認（必要ならWeb裏取り）し、証拠の落ちる所に結論を落とす（阿波説に不利でも正直に。例：銅鐸の突線鈕式は近畿中心分布→阿波は受容側と書く）。メモリ `feedback_dedup_first_prevents_fabrication` / `feedback_backlog_closure_staleness` 参照。
5. **俗説・神代文字・保留層には適用しない** — 磯輪上／四国遍路／カタカムナ／ホツマ／竹内文書／日ユ同祖／阿波文字 等（メモリ `feedback_backlog_self_gating` の保留層）はテンプレ化せず pending 維持。

## 標準frontmatter

```yaml
---
aliases: [読み, 異表記1, ...]
tags: [神/X or 氏族/Y, 関連テーマ, 阿波説]
分類: 神格 / 氏族 / 理論・研究
旧国: 阿波国 / ...   # 論点に地理がある場合のみ
deities: ["[[当該神格や中心人物]]"]   # 神格ノートの場合
clans: ["[[関連氏族]]"]                # 氏族ノートの場合
evidence_type: primary_source_based / shrine_origin / blog_hypothesis / fringe_hypothesis
confidence: 1-5（5が最高）
---
```

`evidence_type` の選択：
- `primary_source_based` — 記紀・延喜式・風土記等の一次史料で骨格が裏付く
- `shrine_origin` — 社伝・縁起が主たる典拠
- `archaeological_evidence` — 発掘・出土・編年など考古学的物証が骨格（02_考古学・物証の既存ノートで使用。阿波説接続は別途留保）
- `blog_hypothesis` — 阿波説ブログ・note記事が主たる論証元
- `fringe_hypothesis` — 俗説・神代文字系（原則テンプレ化せず保留。やむを得ず触る場合は最厚の留保）

近代化では **既存の evidence_type 値を尊重して保持**（上記enum外の値でも勝手に正規化しない）。無い場合のみ推定追加。

近代化では **frontmatter は既存の値を保持** し、`evidence_type`/`confidence` が無い場合のみ
本文の論拠の質から推定して追加する（断定的なら下げる方向で慎重に）。

## 厳守ルール（shrine-note-template と共通）

1. **wikilinkは basename 形式のみ** — `[[フルパス/X.md]]` 禁止（赤リンク化リスク）
2. **BOMなしUTF-8**、**改行は元ファイルの方式を維持**（Vaultは概ねCRLFだが個別確認）
3. **既存ノートを破壊しない** — 近代化は内容保存リストラ。削除行が多くても「再配置・拡充」であって「内容消失」でないこと
4. **過剰一般化を避ける** — 阿波説の解釈と通説を明確に区別
5. **留保セクション必須** — `blog_hypothesis`/`fringe_hypothesis` では特に厚く
6. **alias衝突回避** — 新規alias追加時は既存ノートと衝突しないか確認

## 近代化フロー（analyze → review → apply。L-004準拠）

一つのエージェントに「判定」と「執筆」を同時にさせない。確認バイアス命題では特に。

1. **analyze**：対象ノートを読み、次を返す（書き換えはしない）:
   - 再構成プラン（既存の主張 → どの節に行くか の対応）
   - 提案 frontmatter（既存値保持＋不足分の推定）
   - **捏造フラグ** `needs_fabrication`：テンプレを埋めるのに新規主張が要るなら true
   - **skipフラグ** `already_modern`：既に新フォーマットなら true（過剰包含分の除外）
2. **review**：人間（私）が `needs_fabrication` / `already_modern` を scan。前者は節省略方針、後者は対象外に。
3. **apply**：内容保存リストラのみ実行。新規主張は書かない。旧見出し→番号節への置換と frontmatter 補完が主作業。

## フォルダ単位シャーディング（大量近代化時）

フォルダごとに end-to-end（analyze→review→apply→検証→報告）で1フォルダずつ完結させる。
全件 analyze してから全件 apply はしない（差分レビュー不能・blast radius大）。
小さいフォルダ（02_考古・05_地理）でパイプライン検証 → 大きいフォルダ（03_氏族）へ。

候補リストは `D:/Vault/_work/_modernize/` の分類スクリプトで生成（`classify.py` 最広 / `refine.py` strict 2条件）。

## 検証（apply 後・フォルダ単位）

### 最重要：逆方向リンクdiff（apply ゲート）
**「新ファイルのリンクが解決するか」だけでは不十分** — それは生き残ったリンクしか見ず、
**ドロップしたリンクを構造的に検出できない**。必ず逆方向で diff する：

```
旧ファイルの全 [[...]] ⊆ 新ファイルの全 [[...]] ∪ {意図的に retarget したもの}
```

旧リンクで新ファイルに無いものは「ドロップ」。各ドロップをリンク先で分類：
- **Vault内の公開ノート**（式内社/理論・研究 等）→ **保持必須**。絵文字見出しwikilink（`[[📜 X|X]]` 等の子`_詳細`ノートへのリンク）を平文見出しに潰すと**子ノートをorphan化**する。リンクとして残すこと。
- **`資料/Web_Archives/` 配下**（sync対象外＝非公開）→ 平文化＋出典URL保持は許容（公開時dewikifyと同じ挙動）。ただし**ログする**、黙ってドロップしない。
- **赤リンク**（実在しない）→ 既存 dewikify ルールに従う。

### wikilink形式の例外（近代化特有）
原則は basename だが、**フルパスが正しく解決し AND basename が同名衝突する**場合は
**フルパス `[[理論・研究/.../X|X]]` を維持**する（basenオーム化はコイン投げに劣化させる）。
このVaultではフルパスwikilinkは45+ファイルで使われ、Quartz dewikify も壊さない正当形式。
basename原則の目的は「フルパス由来の赤リンク回避」であって、衝突回避には適用しない。

### truncation を補完しない
旧本文が「…」で途切れている箇所は**そのまま「…」を残す**。文意を推測して文を完成させると
**捏造**になる（例：「初期ヤマト王権の…」→「軍事力を支えたとされる」は禁止）。

### その他
```bash
pwsh -NoProfile -Command "& '<vault-verify-notes.ps1のパス>' -Notes @('basename1',...)"
```
- reach（ハブ到達）／outbound（赤リンク）／alias衝突
- 改行コード：元ファイルが LF なら**LFを維持**（`uv run python` でbytes処理。Writeツールは CRLF を出すので書込後に LF 統一が要る）、BOMなし
- claim-loss チェックは apply 内で（prose の主張 + リンク の両方）。公開時 numstat は近代化では全件発火し無意味なので頼らない

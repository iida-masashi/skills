# essay-note-template

阿波説Vault `D:\Vault\awa` で、神格・氏族・天皇伝承・渡来人・地政学などの**論考型ノート**（神社ノート以外）を近代化（旧フォーマット→統一形式）または新規作成する際の標準テンプレート。[`shrine-note-template`](../shrine-note-template/)（神社専用）の論考版にあたる姉妹スキル。

## 使う場面

以下のいずれかを行うときに使う。

- 旧フォーマットの神格論・氏族論・伝承論ノートを、統一形式に**近代化**する
- 神格・氏族・天皇伝承・渡来人・地政学・考古などの論考型ノートを**新規作成**する

神社ノート（式内社・式外社）には使わない。そちらは `shrine-note-template` の担当。目次・MOC・ポータル・索引・dataview動的ノートにはテンプレを適用しない（触らない）。

使い分けの詳細:

| ノート種別 | テンプレ | 配置先(例) |
|---|---|---|
| 神社（式内社・式外社） | `shrine-note-template` | `式内社/...` |
| 神格（祭神そのものの論） | 本テンプレ | `理論・研究/03_氏族・系譜/神々の系譜/...` |
| 氏族・系図 | 本テンプレ | `理論・研究/03_氏族・系譜/各氏族の研究/...` |
| 天皇・伝承・渡来人・地政学・考古 | 本テンプレ | `理論・研究/01_〜05_/...` |
| 目次・MOC・ポータル・索引・dataview動的 | テンプレ非適用（触らない） | — |

## 近代化の鉄則

近代化とは**内容保存リストラ（content-preserving restructuring）**であり、**新規主張の生成ではない**。

1. **既存の主張は一つも失わない** — 旧ノートの全アサーションが、再編後も（並べ替え・節分けされて）残ること。
2. **埋めるために捏造しない** — テンプレの節が既存材料で埋まらないなら、その節は省くか薄いままにする。空欄を埋めるために新しい史実主張を書かない。
3. **通説と阿波説を分離** — 記紀・通説の記述と、阿波説の飛躍（比定・読み替え）を必ず別の層に置く。
4. **素材ノートの断定を継承しない** — 一次データノートや既存ノートが断定調で書いていても、それを新ノートにそのまま引き継がない。一次事実だけ抽出し、解釈・帰属は `[!note]` で仮説隔離する。考古系では通説を一次確認し、証拠の落ちる所に結論を落とす（阿波説に不利でも正直に書く）。
5. **俗説・神代文字・保留層には適用しない** — 磯輪上／四国遍路／カタカムナ／ホツマ／竹内文書／日ユ同祖／阿波文字等はテンプレ化せずpending維持。

## 生成されるノートの構造

標準frontmatter:

```yaml
---
aliases: [読み, 異表記1, ...]
tags: [神/X or 氏族/Y, 関連テーマ, 阿波説]
分類: 神格 / 氏族 / 理論・研究
旧国: 阿波国 / ...   # 論点に地理がある場合のみ
deities: ["[[当該神格や中心人物]]"]   # 神格ノートの場合
clans: ["[[関連氏族]]"]                # 氏族ノートの場合
evidence_type: primary_source_based / shrine_origin / blog_hypothesis / fringe_hypothesis
confidence: 1-5（5が最高）
---
```

`evidence_type` の選択肢:

- `primary_source_based` — 記紀・延喜式・風土記等の一次史料で骨格が裏付く
- `shrine_origin` — 社伝・縁起が主たる典拠
- `archaeological_evidence` — 発掘・出土・編年など考古学的物証が骨格
- `blog_hypothesis` — 阿波説ブログ・note記事が主たる論証元
- `fringe_hypothesis` — 俗説・神代文字系（原則テンプレ化せず保留）

近代化では既存の `evidence_type` 値を尊重して保持し、無い場合のみ本文の論拠の質から推定して追加する。

標準セクション構造（5＋α、神社版より軽量）:

1. **命題の構造** — 通説と阿波説を対比する表
2. **本論** — 旧ノートの本文を論点ごとに `###` 小見出しで再編（内容は削らず配置を変えるだけ）
3. **阿波説における意義** — この命題が阿波説全体でどう位置づくか
4. **関連ノート（Vault内）** — 旧ノートにあったリンクをbasename形式で保持
5. **留保（中立的併記）** — 阿波説的解釈と通説の違い、evidence_typeとconfidenceの明示

α（任意・材料がある時のみ）: 基本情報の表（神格ノート）、同一神異名群／複数系図の対比表（系図ノート）。

## 厳守ルール（shrine-note-templateと共通）

1. wikilinkはbasename形式のみ（`[[フルパス/X.md]]` 禁止。赤リンク化リスク）
2. BOMなしUTF-8、改行は元ファイルの方式を維持
3. 既存ノートを破壊しない（近代化は内容保存リストラ）
4. 過剰一般化を避ける（阿波説の解釈と通説を明確に区別）
5. 留保セクション必須（`blog_hypothesis`/`fringe_hypothesis` では特に厚く）
6. alias衝突回避（新規alias追加時は既存ノートと衝突しないか確認）

## 近代化フロー

analyze → review → apply の3段階（1つのエージェントに「判定」と「執筆」を同時にさせない）。

1. **analyze** — 対象ノートを読み、再構成プラン・提案frontmatter・捏造フラグ（`needs_fabrication`）・skipフラグ（`already_modern`）を返す（書き換えはしない）
2. **review** — 人間が両フラグをscanし、`needs_fabrication` は節省略方針、`already_modern` は対象外にする
3. **apply** — 内容保存リストラのみ実行。新規主張は書かない。旧見出し→番号節への置換とfrontmatter補完が主作業

大量近代化時は、フォルダごとにanalyze→review→apply→検証→報告を1フォルダずつ完結させる（全件analyzeしてから全件applyはしない）。

## 検証

apply後、フォルダ単位で以下を確認する。

- **逆方向リンクdiff**（最重要）— 「新ファイルのリンクが解決するか」だけでは、旧ファイルからドロップしたリンクを検出できない。旧ファイルの全wikilinkが新ファイルに含まれるか（意図的なretarget除く）を逆方向で確認する。Vault内の公開ノートへのリンクは保持必須。
- **wikilink形式の例外** — 原則basenameだが、フルパスが正しく解決しbasenameが同名衝突する場合はフルパスを維持する
- **truncationを補完しない** — 旧本文が「…」で途切れている箇所はそのまま残す（文意を推測して完成させると捏造になる）
- 改行コード・BOMなしの維持
- `vault-verify-notes.ps1` によるreach（ハブ到達）／outbound（赤リンク）／alias衝突チェック（任意）

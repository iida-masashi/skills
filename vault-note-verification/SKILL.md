# vault-note-verification

阿波説 Vault の **既存ノート** を点検・改訂する際の事実照合手順。新規ノートの作成様式は [[shrine-note-template]]（論考は [[essay-note-template]]）に従い、本スキルは「既にある記述をどう検証し、どう直すか」を定める。

2026-11-15 に本体ノート全507件を対象に実施した照合で確立した手順である。

## 大原則

- **出典で確認できない事実は書かない。推測で補完しない**（座標・年号・祭神名・所在地を含む。本人指示 2026-11-15）
- 確認できない主張は削除せず **「未検証」** と明示して留保へ分離する。取得できない資料は **「未取得」** と明記する
- **エビデンス（一次資料）は必ず MD で残す**（Vault の運用原則）。一次資料の MD 化には convMD を使う

## 手順

1. **バックアップ** — 修正前に原文を監査用フォルダへ保管する（`<basename>_修正前.md`）
2. **エビデンス保存** — Wikipedia・公式サイト・神社庁・自治体等の公的資料を convMD で `資料/04_Web記事・ブログ/` へ保存する。一次資料は Wikisource 原文（『延喜式』神名帳・『古語拾遺』・『先代旧事本紀』等）を優先する
3. **照合** — 社名表記・社格・祭神・所在地・年号・系譜を原文・公的資料と照合する。Wikipedia と原文が食い違う場合は **原文を優先** する
4. **訂正** — 検証できた誤りは根拠つきで訂正する。阿波説の解釈自体は残すが、事実と解釈を分離して提示する
5. **分離** — 確認できない主張は未検証として留保へ番号付きで明記する。未取得の資料・サイトも同様に番号付きで明記する
6. **正規化** — frontmatter を [[shrine-note-template]] の標準形式へ（列挙値厳格・`confidence` は数値）。神社ノートは12セクションへ移行する。索引・論考・詳細サブノートは既存の構成を活かし、12セクションへの強制移行はしない
7. **改訂記録** — 留保に改訂記録（日付・照合内容・訂正点）を必ず残す
8. **検証** — 機械チェックを行う：神社ノートは12セクション・`[!summary]` あり、dataview ブロックなし、フルパス wikilink なし、frontmatter の列挙値が定義内、`confidence` が数値

## 頻出の誤りパターン（2026-11-15 全507件照合より）

- 論社の現行祭神を、式内社の本来の祭神と取り違える（神名帳は祭神を記録しない）
- 社格「大」を「名神大」とする
- 『阿波志』等の二次資料の記載内容の誤記
- 神名帳の構造に関する枠組み自体の捏造（「二社別記」「一座を争う論社」等）
- 座標の大幅な誤値（他県を指す等）
- 神名帳に存在しない社名・神名の創作
- 史料引用文の改変・誤帰属

個別の照合ルール（祭神・社格・論社・座標・引用）は [[shrine-note-template]] の「事実照合ルール」に定める。

## 詳細サブノートの扱い

- 照合時に内容の厚みを評価する。固有の実質的内容が少なく、リンク列挙や本体ノートの再掲が大半なら「薄い」として **本体ノートへ統合する**（本人指示 2026-11-15）
- 統合の手順：固有リンクは本体の §11（関連ノート）へ、検証結果・未検証事項は本体の留保へ移し、本体の改訂記録に統合した旨と内訳を明記する。サブノートは監査用バックアップへ移動し、Vault 内の参照リンクを本体へ付け替える

## 重複ノートの扱い

- 異体字（売／賣など）で同一対象のノートが並立していないか確認する
- 一本化するかどうかは **本人の判断を仰ぐ**。決定後は、敗れた側をバックアップ保管のうえ削除し、参照リンクの付け替え、正ノートへの alias 追加、留保への統合記録を行う

## 参照サイトの承認

- 参照に承認が必要な WEB サイトが出た場合は、承認を待たずスキップし、「未取得（承認待ちのためスキップ）」と留保に明記する（本人指示 2026-11-15）。本人が後でまとめて承認する

## 反映

- 作業単位で git commit / push はしない。GitHub への反映は全作業の最後にまとめて行う（本人指示 2026-11-15）
- スナップショット送信では削除できないため、削除・改名したファイルの旧パスは削除リスト（pending-deletions）に記録しておき、最終反映時に個別に削除する

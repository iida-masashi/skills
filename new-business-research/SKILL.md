# New Business / M&A Research（新規事業・M&A候補調査）

特定企業（例: サッポロ）の「新規事業」「M&A候補」「中長期戦略シナリオ」を、**一次資料を保存してから**書く調査ワークフロー。サッポロ調査（2026-11、cpg Vault `05_Beverage_and_Drinks` の 17〜19 と `06_Market_and_Environment`）で実証した手順と、踏んだ罠をまとめる。

**核心原則**
1. **事実・評価・仮説を別ノートに分ける**。事実（現在地）→ 評価（候補・新規事業案）→ シナリオの順に、前のノートへリンクで積む。仮説は ⚠️、確率は付けない（根拠のない確率は作らない）。
2. **既存ノートを土台にしない**。確度タグも出典リンクもない旧ノートは、数値の幅表記・未来形・取得額の記載など「原典を見ていない兆候」を疑い、一次資料と突き合わせる。食い違いは旧ノートを黙って直さず、新ノートに食い違い表を作って報告する。
3. **候補は「数を先に決めて埋める」のではなく、実在・所有者・買収可能性を確認できたものだけ**評価する。確認できない項目は空欄・保留にする。
4. **市場共通の事実（市場規模・規制・チャネル・業界M&A）は企業ノートに混ぜない**。市場共通フォルダ（cpg なら `06_Market_and_Environment/`）に置き、企業ノートからリンクする。
5. **subagent の主張は、保存した原文で照合してから反映する**。照合できないものは ⚠️（報告値・原文未照合）と明記する。

## 使う場面 / 使わない場面

- 使う: 「X社の新規事業を考えたい」「M&A候補先を調べて」「中長期の戦略シナリオを作って」「外部環境・PPM・市場規模・チャネル・規制の観点で整理して」
- 使わない: 単発の会社概要（WebSearch/WebFetch で足りる）、株価・財務分析が主目的、業界の SCM 構造の調査（`value-chain-research`）。

## 手順

### 0. 着手前（オリエンテーション）
- 保存先 Vault の `rules/`（cpg なら `rules/06_cpg.md`・`rules/02_content_integrity.md`）と、既存の同社ノートを読む。既存の一次資料（`sources/`）の有無を `rg -l` で確認する（重複取得を避ける）。
- 対象企業の**直近の大きな変化**（組織再編・商号変更・事業売却・提携）を先に検索する。今日の日付を確認し、「未来形で書かれた事項がすでに起きていないか」を疑う。

### 1. 企業の一次資料を保存する（convMD）
優先順位: ①最新の決算短信 ②中期経営計画（直近の版。新しい版が出ていないか IR サイトのリンクから探す）③中長期戦略・M&A 方針の適時開示 ④重要な個別適時開示（事業売却・提携）⑤格付会社（JCR 等）の見解 ⑥統合報告書。
- convMD は JPX（`www2.jpx.co.jp`）の PDF を取得できる。**WebFetch は JPX で 403 になる**ので、取得は convMD、読解は保存した md を使う。
- IR サイトの一覧ページは JS 駆動で WebFetch が空になりがち。**ナビゲーションのリンク先（例: `/who-we-are/pdf/Medium_Term_Management_Plan….pdf`）を拾って直接 convMD に渡す**。
- 取込後に必ず確認: ① `source:` に原典 URL がある ② 本文が空・ナビゲーションだけでない（旧リリースの URL がサイトのトップへリダイレクトされ、無関係な md になる例があった）③ 表が文字化け・切り詰めされていないか。壊れたものはスクラッチパッドへ `mv` で退避する（`rm` は権限で止められる）。
- ファイル名は取込後に意味のある名前へ改名する（`Sapporo_2026-07-06_…_適時開示.md` のように 会社_日付_内容）。wikilink の basename になるので、全 Vault で一意にする。
- 5MB 超の取込は `sources/` に置かず原典 URL のリンクだけ残す（cpg ルール）。`.convmd.db`・`.chroma_db` は作業ファイルなので Vault に残さない。

### 2. 市場・規制・チャネルの一次資料を保存する
- 市場規模・成長率: 官公庁統計（酒類なら国税庁「酒のしおり」「酒レポート」の課税数量表）。業界団体・調査会社のデータは、有料・非公開で取れないものは**同社資料に載る引用値として「出典: Euromonitor（同社資料）」と書き、原データ未確認と注記**する。
- 規制: 財務省・厚労省などの公式ページ。税率改正は**施行済みかどうか**を日付で確認する。
- チャネル: 国税庁「酒類小売業者の概況」など。**調査の対象範囲（小売業者の申告か、飲食店を含むか）を注記**する。
- PDF の文字化け（フォント由来）は抽出が壊れる。タイトルと数か所を目視で確認し、使えなければ退避する。
- sec.gov は convMD が 403（User-Agent 要求）。User-Agent に利用者のメールを入れない。取れない一次資料は無理に回避せず、二次資料の報告値として ⚠️ にする。

### 3. 調査の観点（外部環境 → 現在地 → PPM）
1. **現在地**: 直近決算の売上・事業利益・ROE、事業構造、組織、格付、財務規律（格付・レバレッジ上限）、**成長投資枠とキャッシュ・アロケーション**、ハードルレート、M&A 体制。
2. **旧ノートとの食い違い表**（あれば）。
3. **すでに実行した動き**（提携・売却・再編）。新規事業案が既存の動きの言い換えにならないよう、先に列挙する。
4. **PPM**: 相対シェアが一次資料で数値化できないときは**定量 PPM にせず**、「市場の方向性 × 同社の数量成長・利益率（代理指標）」の**定性配置**であると明記し、⚠️ で出す。セグメント別の数値は、取得できた期（中間期など）を明記し通期と混ぜない。
5. **市場・規制・チャネル**は市場共通ノートに書き、企業ノートには要点とリンクのみ置く。

### 4. 競合・候補の調査（subagent の使い方）
- 並列は 3 本まで。例: ①競合・業界の M&A 動向、②海外候補、③国内候補。
- プロンプトに必ず書く: 今日の日付、対象企業の**公表している M&A 領域**、確認項目（実在・規模・**現在の所有者**・直近の売却/提携報道・対象企業との相性）、「WebFetch で開いた内容だけを書く／確認できないものは『未確認』／ファイルは作らない」。
- 返ってきた報告は**そのまま使わない**。重要な候補・案件は公式リリースを convMD で保存して照合する。**金額・株主構成・評価額は、保存した原文に無ければ ⚠️（報告値・原文未照合）**にする。subagent が「確認した」と書いても、集計サイト（EDINET-db 等）の二次数値と、保存した原文の記載が一致しないことがある（大株主の構成が保存ページに無かった例）。
- 「すでに他社の傘下」の候補（例: キリンが 33.3% 保有、他社が TOB 済み）は**対象外**として理由を書く。**競合の買い手がいる領域**（ノンアル等）は「窓が閉じつつある」として扱う。

### 5. 候補の評価基準（スクリーニング）
同社の公表条件から作る: ①領域適合 ②ハードルレート・「自社株買いよりリターンが高いこと」③規模（成長投資枠 − 実行済み案件の残り。設備投資を含むため M&A に回せる額は小さい）④財務規律（格付・レバレッジ上限）⑤取得可能性（創業家支配・大株主・競合の持分）⑥実行体制。
- 候補表は「実在・規模／所有・取得可能性／評価（⚠️）」の 3 列。優先度は**高・中・低・保留・対象外**で付け、理由を 1 文で書く。
- 取得だけでなく、**製造提携 → 少数出資 → 取得**の段階案も検討する（価格・支配権のハードルが高い候補ほど有効）。
- 実需（例: 米国向けノンアルの現地生産移管）を探す。**同社の発言・報道に出ている実際の課題**に紐づく候補を優先する。

### 6. 新規事業案
- 「すでに同社が表明している新規事業」を先に表にし、**追加で検討する価値がある案**だけを優先度順に出す。各案に「根拠となる事実」「論点・リスク」「優先度」を付ける。
- **見送る案と理由**も書く（例: 同業クラフトの追加買収は市場縮小下で意義が薄い）。

### 7. 中長期シナリオ（3 案）
- 軸が重ならない 3 案にする（例: A 国内深耕・資本還元／B 買収拡張／C 提携・ライセンス型）。確率は付けない。
- 各案に: ストーリー、根拠となる事実、資本配分のイメージ（⚠️）、成立条件、**サイン（その案に向かう兆候）**、弱点。最後に 3 案の比較表（同社の公表目標との適合）、組み合わせ（基本線 A＋C ＋ B を限定追加 など）、分岐を決める要因、**撤退・見直し基準**、次に確認すべき未確認項目。
- 利益寄与の粗い試算は、**前提（ハードルレートの定義が不明など）を明記し「桁の目安」と書く**。取得できていない前提（純有利子負債の実額など）は計算せず「未取得」と書く。

## ノートの構成（cpg Vault の例）

```
05_Beverage_and_Drinks/
  06_Market_and_Environment/       市場共通（市場規模・規制・チャネル・業界M&A）＋ 00_INDEX
  04_Company_Studies/
    17_<社>_新規事業・M&A候補調査_現在地・PPM        … 事実（固有のみ）
    18_<社>_新規事業案とM&A候補の評価_…            … 評価・仮説
    19_<社>_中長期戦略シナリオ3案_…                 … シナリオ
sources/beverage/<社>_newbiz/, <市場>/, competitor_ma/, ma_candidates/   … 保存した一次資料
```
- 各ノート冒頭に確度タグの凡例（✅✅ 保存した一次資料／✅ 二次資料／⚠️ 仮説・未確認）を置く。
- 末尾に「次に確認すべき未確認項目」と「資料一覧（`[[basename]]`）」を置く。

## 完了前チェック

1. 追加した `[[wikilink]]` がすべて実在ファイルに解決し、同名衝突がない。フルパス wikilink がない。
2. 改行コードが同フォルダの既存ノートと同じ（cpg の企業研究は CRLF）。BOM なし。ファイル名 255 バイト以下。
3. INDEX・MOC から新ノートにリンクしてある。BACKLOG は GitHub Issues 管理（起票はユーザー承認後）。
4. `mermaid-hygiene` の `validate_mermaid.py` を対象に実行し 0 件。
5. 既存ノートから内容を移すときは、記述を変えず、元の節に移設先へのリンクを残し、旧版（git）と行単位で照合する（欠落 0）。
6. コミットは対象パスを明示してステージ。**push はユーザー承認後**、`vault-publish` の手順（sync → build → push）で行う。他セッションの未 push コミットが含まれる場合は、公開前にユーザーへ確認する。
7. 最終報告には、**確認できなかった項目と、⚠️ にした数値**を必ず書く。

## よくある罠

| 罠 | 対処 |
|---|---|
| 旧ノートの数値・取得額を引き継ぐ | 一次資料で再確認。食い違いは表にして報告 |
| 「検討中」の事項がすでに実行済み（または撤退済み） | 日付と最新の適時開示を確認（Stone 譲渡の例） |
| 市場規模・シェアの数値が出典不明 | 官公庁統計か同社資料の引用値に限り、原データ未確認と注記 |
| 候補がすでに他社の持分 | 所有者を一次/準一次で確認し、対象外にする |
| subagent の金額・株主構成を転記 | 保存原文と照合できなければ ⚠️ |
| 取込ファイルがナビゲーションのみ | 内容を確認し、無関係なら退避して別 URL を探す |
| 通期と中間期の数値の混在 | 期を明記。通期が取れなければ表に載せない |
| 確率・断定的な推奨 | 付けない。サインと分岐条件で示す |

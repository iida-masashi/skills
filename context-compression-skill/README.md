# Context Compression Skill

ツール出力をコンテキストウィンドウに入れる**前**に圧縮・フィルタするための指示書（rtk-ai/rtk の発想を踏襲）。

## 使われ方（3層防衛）

1. **常時適用のグローバル指示**: `~/.claude/CLAUDE.md` と `~/.gemini/GEMINI.md` の「コンテキスト圧縮」節に約10行の要約を配置し、毎ターン効かせる。
2. **詳細リファレンス（本スキル）**: ビルド・テスト・巨大ファイル・Notebook・表データ・MCP・広域検索・Web 調査など、大量出力が見込まれる場面で読み込まれる。本文自体もトークンを消費しすぎないよう高密度に圧縮してある。
3. **機械的ガードレール（PreToolUse フック）**: `C:\Users\iidam\gemini\tools\hook-guard.ps1` により、ロックファイルや `.ipynb`・Minified ファイルの直接 Read、500行/25KB超ファイルの `limit` なし一括 Read、除外なし再帰検索（`ls -R` / `Get-ChildItem -Recurse`）を実行前に機械的にブロックする。

## 設計上の要点

- **終了コードを落とさない**: Bash の `cmd | tail -30` は失敗を exit 0 に見せるため、ログファイル経由 + `echo "exit=$ec"` を正規形とする。
- **行数だけでなくバイト数・特殊形式も制限**: 300行以下でも 20KB 超（Minified・1行JSON）や `.ipynb`（Base64出力）は直接 Read しない。
- **圧縮しない場面を明記**: レビュー・監査・バグ原因特定・Edit 用文字列作成・事実検証では、断片ではなく関数/ファイル単位で通読する。
- **サブエージェントの結果は未検証扱い**: 返されたパス・ID・名前は使う前に実在確認する。

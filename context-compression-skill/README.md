# Context Compression Skill

出力がコンテキストウィンドウに入る**前**に圧縮・フィルタするための13原則を規定する指示書（rtk-ai/rtkの思想を踏襲）。スクリプトは持たず、SKILL.md単体でエージェントの振る舞いを規律する。

| Document | Purpose |
|----------|---------|
| [SKILL.md](SKILL.md) | 13原則の本文・ツール語彙対応表・アンチパターン変換表・安全弁 |

## 発動条件・使われ方

このスキルはCLIコマンドを持たない。Claude Code/Gemini CLI双方の環境で、エージェントがシェルコマンド実行・検索・ファイル読み込みを行う**都度**適用される運用指示書であり、ユーザーが明示的に呼び出すものではない。

本文は実行環境に依存しない汎用語彙（「検索ツール」「部分読み込み」等）で書かれており、実際のツール名は環境ごとに以下のように読み替える。

| 汎用概念 | Gemini CLI | Claude Code |
|---|---|---|
| 検索ツール | `grep_search` | `Grep`（`output_mode`, `-C` context, `head_limit`） |
| 部分読み込み | `read_file` の `start_line` / `end_line` | `Read` の `offset` / `limit` |
| ファイル一覧 | `glob` / `list_directory` | `Glob` |
| 末尾抽出 | `Select-Object -Last 30`（PowerShell） | `tail -30`（Bashツール） |

## 13原則

1. **コマンド実行時の静音化** — `npm install --quiet --no-progress`, `git status -s`, `pytest --tb=short -q` 等でログ自体を減らす。
2. **エラーログの蒸留** — 末尾30行程度に絞る、またはファイルへリダイレクトして`Exception`/`Error`周辺だけを検索抽出する。
3. **ファイル構造の「目次」抽出** — `def `/`class `等シグネチャだけ検索してAST的骨組みを把握し、対象行だけを部分読み込みする。
4. **差分ベースの観測** — 全ファイル再読み込みではなく`git diff`/`git diff --name-only`で変更点だけを見る。
5. **出力フォーマットの高密度化** — インデント無しJSON、CSV/Markdownテーブルなどトークン効率の高い形式を強制する。
6. **データフレームの極限圧縮** — 生データ全出力を禁止し、`df.glimpse()`や`df.schema`、`head(3)`+`tail(3)`に圧縮する。
7. **セマンティック・ディフ** — `git diff -U0`（コンテキスト行ゼロ）や構造ベースの変更点抽出で「何が変わったか」だけを見る。
8. **プログレッシブ・ディスクロージャー** — ファイル名/構造→シグネチャ→対象行の3段階で必要性が証明されるまで詳細を引き出さない。ただし**300行以下の小ファイルは一発で全体を読んでよい**（往復コストの方が高いため）。300行超のファイルにのみ段階的開示を適用する。
9. **サブエージェント委譲** — 広域探索はサブエージェントに委譲し、結論（ファイルパス・要約・判定）だけをメイン文脈に受け取る。1サブエージェント1タスクで「何を返すか」を指定して投げる。
10. **構造化出力の射影** — `gh pr list --json number,title -q '.[]'`や`jq -c '.items[] | {id, status}'`のように、必要フィールドだけを機械可読形式で取り出す。SQLは`SELECT *`禁止、必要列+`LIMIT`。
11. **数値基準（デフォルトの上限）** — 単一ツール出力は原則**100行以内**。100行超が予想されるコマンドは一時ファイルへリダイレクトし検索・末尾抽出で取り出す。`git diff`はまず`--stat`で全体像→ファイル単位で個別確認。
12. **アンチパターン即時変換表** — よくある悪手を即座に代替手法へ変換する対応表（下記実行例参照）。
13. **Web検索・Web取得の圧縮** — クエリは固有名詞・年・単位まで絞って一発で当てにいく。検索結果は一次資料らしい1〜2件だけをFetchし、`prompt`引数で必要事実だけ射影する。広域調査はサブエージェント委譲。確度タグ（[一次]/[要検証]等）と出典URLは圧縮後も必ず残す。

## Highlights

- **環境非依存の汎用語彙＋対応表** — 本文はツール名を固定せず、Gemini CLI/Claude Codeそれぞれの実ツールへの読み替え表を別立てで持つ。
- **定性判断ではなく数値基準** — 「原則100行以内」「300行閾値」「末尾30行」など、判断基準を具体的な数値で固定している。
- **サブエージェント委譲を最大の圧縮手段と明記（§9）** — 広域探索はメイン文脈でいくら出力を削っても積み上がるため、中間結果はサブエージェント側で消費させ結論だけを持ち帰る設計。
- **安全弁（圧縮しすぎの禁止）** — 圧縮は成功パスの最適化であり、失敗の証拠を落とすためのものではないと明記。exit codeと失敗シグナルは絶対に落とさない。コマンド失敗時は次の1回はフィルタを緩めて（末尾行数を増やす・context拡大・フルログをファイル保全）再観測してよく、圧縮より原因特定を優先する。末尾抽出でroot causeが窓外に落ちた疑いがあればログ先頭側も検索する。
- **§13でも確度タグは維持** — Web調査を圧縮しても、[一次]/[要検証]等のタグと出典URLは要約後も残し、検証可能性を犠牲にしない。

## 実行例

アンチパターン即時変換表（§12）より抜粋。左を打ちそうになったら右に変換する。

| アンチパターン | 代替 |
|---|---|
| `cat <大ファイル>` / 全行読み込み | 構造把握 → 部分読み込み（§3, §8） |
| `ls -R` / 再帰フル一覧 | パターン指定のファイル検索、深さ制限 |
| `npm install`（素のまま） | `npm install --quiet --no-progress` |
| `git log`（引数なし） | `git log --oneline -n 5` |
| `git diff`（いきなり全体） | `git diff --stat` → ファイル単位 |
| DataFrame の `print(df)` | `df.glimpse()` / schema + head/tail（§6） |
| ヒットしたURL全部をFetch | 一次資料と疑われる1〜2件に絞ってFetch（§13） |

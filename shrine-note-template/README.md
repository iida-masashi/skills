# Shrine Note Template Skill

阿波説Vault `D:\Vault\awa` で神社・神格・系図の専門ノートを作成する際に使う、標準12セクション構造テンプレートとガイドライン。神社名・所在地・主要論点を渡すと、frontmatter + 命題構造 + 由緒 + 阿波説的意義 + 留保を含む統一フォーマットでノート生成を支援する。

| Document | Purpose |
|----------|---------|
| [SKILL.md](SKILL.md) | frontmatter定義・12セクション構造・厳守ルール・検証フロー |

## どういう場面で使われるか

- 阿波国式内社、房総（千葉県）の式内社、常陸国・武蔵国の式内社ノートを新規作成するとき
- 神格専門ノート（`理論・研究/03_氏族・系譜/神々の系譜/その他の神々・人物/`）を作成するとき
- 系図専門ノート（`理論・研究/03_氏族・系譜/各氏族の研究/<氏族>/`）を作成するとき

対象と配置先は以下の対応表で定義されている。

| 対象 | 配置先 |
|---|---|
| 阿波国式内社 | `式内社/01_阿波国/01_郡別調査/<郡名>/` |
| 房総（千葉県）式内社 | `式内社/02_安房・上総・下総（千葉）/<旧国名>/` |
| 常陸国・武蔵国 | `式内社/03_常陸・武蔵（北関東）/<旧国名>/` |
| 神格専門ノート | `理論・研究/03_氏族・系譜/神々の系譜/その他の神々・人物/` |
| 系図専門ノート | `理論・研究/03_氏族・系譜/各氏族の研究/<氏族>/` |

このスキル自体はスクリプトを持たず、frontmatterスキーマとセクション構成・執筆ルールを定義する指示書である。

## 生成されるノートの12セクション構造

1. **命題の構造** — 通説と阿波説を対比する表
2. **基本情報** — 社名・所在地・創建・主祭神・配祀・延喜式表記・社格・位置付けの表
3. **祭神と社伝** — 祭神の系譜・神話的背景、社伝の主要な物語
4. **歴史** — 創建・社格変遷・中世以降の変遷
5. **（核心論点・テーマ別セクション）** — 神社固有の重要論点をテーマ別に展開
6. **阿波説における意義** — 論点ごとの小見出し（6-1, 6-2, ...）
7. **関連神社・関連氏族** — 阿波忌部の祭祀軸／関連神格／関連氏族へのwikilink
8. **現地情報・Google Maps地理情報** — 住所・実測座標・スポットURL・アクセス・ストリートビュー観察情報
9. **参照ブログ・Web資料** — 出典系統別（chiba_jinja系／fusa系／awa-otoko系など）のwikilink
10. **史料** — 一次史料（古事記・日本書紀・古語拾遺・延喜式神名帳）と神社縁起・社伝
11. **関連ノート（Vault内）** — 東遷論／関連神格・系譜／阿波説総合へのwikilink
12. **留保（中立的併記）** — 阿波説的解釈と通説の区別、evidence_typeとconfidenceの明記

冒頭にはfrontmatter（後述）と、核心命題を300字程度で要約する `[!summary]` コールアウトが入る。文末には親ノートとの位置付けを示す一文を置く。

### frontmatterの主な項目

`aliases`、`tags`、`分類`（式内社／式外社／神格／理論・研究／拠点）、`社格`、`旧国`、`旧郡`、`地域`、`location`、`coordinates`（Google Maps実測緯度経度）、`google_maps_url`、`official_website`、`deities`、`clans`、`evidence_type`（primary_source_based／shrine_origin／blog_hypothesis／fringe_hypothesis）、`confidence`（1〜5、5が最高）。

## 厳守ルール

- wikilinkは **basename形式のみ**。フルパス指定（`[[フルパス/X.md]]`）は赤リンク化リスクがあるため使わない
- **BOMなしUTF-8** で保存する
- **既存ノートを破壊しない**（加筆型のみ）
- 阿波説の解釈と通説を明確に区別し、過剰一般化を避ける
- **留保セクション必須**。`evidence_type: blog_hypothesis` 等では特に厚く書く
- ファイルサイズ目安は **5,000〜25,000バイト**（テーマの厚みに応じて調整）
- **dataviewを使わない**。公開先のQuartzはdataviewを描画できないため、` ```dataview ` ブロックは公開サイトで生クエリコードとして露出してしまう。「この神を祀る式内社」のような一覧は最初から静的Markdown表（旧郡昇順、社名は `[[basename]]`）で書く

## 神格ノート・系図ノートの追加観点

神格ノートの場合は、同一神異名群の整理（平田篤胤「一神異名」説など）、複数系図文献（粟飯原家系図／斎部宿祢本系帳／高山家本など）での位置比較、后神・夫神・御子神の系譜、後裔氏族との接続を追加で扱う。

系図ノートの場合は、縦系譜（世代）と横系譜（兄弟・御子）の二軸構造、複数系図の対比表、異名関係の明示、編纂年代と政治的動機を追加で扱う。

## 作成後の検証

ノート作成後は使い捨てスクリプトを書かず、既存の検証ツール（`vault-verify-notes.ps1` / `vault-orphans.ps1` / `vault-thin-notes.ps1`）で reach（ハブ到達）・outbound（赤リンク）・alias衝突・孤立・薄さを確認する運用を推奨している。
